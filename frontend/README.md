# SHPE Northeastern Website

The official website project for the **Society of Hispanic Professional Engineers (SHPE) at Northeastern University**.

We're building a central hub for our chapter where students, members, and sponsors can learn about SHPE Northeastern, explore upcoming events, meet our leadership, and get involved.

This is a student-led project focused on collaboration, learning, and gaining hands-on software development experience.

## Getting Started

**Prerequisites:** Install [Git](https://git-scm.com/), [Node.js](https://nodejs.org/) (a version compatible with this project's Vite release), and [VS Code](https://code.visualstudio.com/) or your preferred editor.

**1. Clone the repository**

`git clone https://github.com/shpe-northeastern/shpe-website.git`

`cd shpe-website`

**2. Install dependencies**

`npm install`

**3. Start the development server**

`npm run dev`

Open the local URL displayed in your terminal (usually `http://localhost:5173`).

### Useful Commands

| Command          | Description                  |
| ---------------- | ---------------------------- |
| `npm run dev`    | Start the development server |
| `npm run format` | Format code with Prettier    |
| `npm run lint`   | Check for code issues        |
| `npm run build`  | Build the application        |

## Contributing

We welcome contributors of all experience levels!

Before starting, please review our **[Contributor Onboarding Guide](https://docs.google.com/document/d/1-tzMTj14AQnXnRdhtF50Qdoj9pY0-pK4hUARZjFWt6k/edit?tab=t.nsf5szm5zb3l#heading=h.36oiu79lvv90)** for step-by-step instructions on using Git, GitHub, and our development workflow.

### Collaboration Guidelines

- **Branches:** Create a separate branch for each task. Do not push directly to `main`.
- **Issues:** Each development task should have a corresponding GitHub Issue.
- **Commits:** Follow Conventional Commits (e.g., `feat: add events page`, `fix: resolve navbar issue`, `docs: update readme`).
- **Pull Requests:** Submit changes through a PR and get at least one other contributor's approval before merging.
- **Code Quality:** Run formatting, linting, and build checks before opening a PR.
- **Communication:** Keep the team updated on progress and reach out when you need help!
